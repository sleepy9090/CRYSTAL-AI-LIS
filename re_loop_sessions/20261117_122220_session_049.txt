I finished Ph7 web 1/8 (design + data export) and marked it done in REVERSE.md. The new exporter's `--check` mode passes all 14 of its checks.

**`docs/architecture_web.md`** is the design for the web port, written before any port code exists. Its main choices:
- **State in RAM arrays at the ROM's addresses.** That way the `--compare` CSV from `tools/emu/compare.py` and the battery-save image work unchanged.
- **No hand-copied tables.** Every table the port uses is loaded from `web/data/`.
- **No bank switching except CHR R0-R5.** The bank-10 screen-page quirk is kept as an explicit branch.
- **Game logic doesn't touch the DOM,** so the Node test harness can run it.
- **Routines that wait across frames (fades, messages, menus) become generator functions,** so they take the same number of frames as in the ROM.

The doc also has the JS module graph, a table mapping each ROM routine to its JS function and module, the state machine and frame flow, the list of `web/data/` files, and the verification plan for Ph7 tasks 3-8.

**`tools/gen_web_data.py`** writes 17 files and a `manifest.json` (size, sha1 and ROM source for each file) to `web/data/`:
- **Raw binary files** that keep ROM addressing: `chr.bin`, `screens.bin` (banks 0-7, page S at S×256), `screens_b10.bin`, `metatiles.bin` (banks 8/9 as `$8000-$BFFF`), raw sound banks 24, 25 and 12, and `dmc.bin`.
- **Decoded JSON** built by the existing decoders, so each format still has one decoder:
  - `palettes.json`
  - `areas.json`: 213 areas with record, spawns, k0-k5 and the handler-1 records
  - `objtypes.json`
  - `metasprites.json`
  - `shots.json`
  - `tables.json`: 39 named tables
  - `ram_labels.json`
- **`text.json` and `sound.json`** are regenerated by their own tools.
