**New tool: `tools/struct_dump.py`**
- `obj` → `docs/obj_struct.txt`: one row per object column (4 zero-page + 32 at `$0300-$06E0`). Each row has the name, read/write counts, fixed-slot refs, banks, which routines write and read it, and how many object type records set it.
- `objtype` → `docs/obj_struct_inits.txt`: the starting values each column gets across all type records.
- `rec <layout> BB:AAAA [n]`: decodes fixed-size records (`area_hdr`, `spawn`, `k1`-`k5`, and the new `hitbox`/`collpair`). Formats with variable length stay in their existing tools. I only spot-checked `k3` on header pointers rather than real exit data, so its output there was meaningless; the `hitbox` and `collpair` dumps match the hand decode.

**What I found**
- **The four unknown columns are resolved:**
  - `$03A0` = `obj_coll`: the high nibble is a collision-group mask, the low nibble picks a hitbox.
  - `$05A0` = `obj_freeze`: while it's non-zero, the object's AI doesn't run that frame.
  - `$0640` = `obj_act_timer`: an attack countdown; at `$0F` the object fires a projectile.
  - `$0660` = `obj_aux`: a per-AI step counter (for example the vanish fade-out).
- **`$0440` renamed `obj_shot_id`** (was `obj_pause_timer`). For shooting enemies it's the projectile id. Wandering NPCs and the walk-and-pause AI reuse it as a pause timer.
- **Object-vs-object collision:**
  - `ObjCollideAll` `26:8F6E` runs once per frame.
  - A 15-record pair table at `26:96F1` checks fixed attacker slots against target slots `$0D-$1E`. Attackers are the player (slot 1), slot 3, slot `$0C`, and the player's shots/sword (slots 2 and 4-11).
  - The overlap test (`26:95F8`) is a plain box check using a 24-entry hitbox table at `26:9691`.
- **Knockback:** the high nibble of `$0340` counts 8 frames. During that time the object is pushed at speed 8 and its AI doesn't run. The player handles its own knockback instead.
- **Projectiles:** `SpawnShot` `26:972D` uses a table at `20:BC00`. Decoding its fields is queued in "gameplay 3/3".
