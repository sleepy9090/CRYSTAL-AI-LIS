**What I added**
- **`web/src/game/obj/sprites.js`**: `spriteDraw()` ports the sprite pass and its three sub-routines (metasprite draw, hiding unused sprites, orbit ring/burst) instruction by instruction. It writes the same zero-page temps the ROM does, so the whole RAM can be compared.
- **`web/data/sprites_b28.bin`**: PRG banks 28-29 exported by `tools/gen_web_data.py`. The port reads the draw-order tables and metasprite records from it by CPU address, the way the ROM does.
- **`tools/emu/sprite_capture.py`**: records RAM when the pass starts and when it returns. `real` mode hooks a normal run; `fuzz` mode fills camera, orbit state, OAM and all 32 object slots with random values, then calls the routine.
- **`web/test/sprite_check.mjs`**: replays every case through the port and diffs all 2KB of RAM, except the stack bytes the 6502 uses for calls. It exits 1 on any difference.
- **`tools/meta_ptr_check.py`**: lists metasprite ids whose pointer leaves banks 28/29.

**How it's checked**
- 52 real passes from the canonical run and 500 fuzz cases all give identical RAM.
- As a negative test, I swapped in the mirrored-x formula REVERSE.md used to document. 250 of the 500 fuzz cases failed, but 0 of the 52 real ones did, because the real run never draws a mirrored sprite. The fuzz set is what covers mirroring, overlays, sinking, OAM overflow and the burst ring.
- The core, world, serve and ppu checks still pass.

**Findings (written to REVERSE.md)**
- **Doc correction:** mirrored records place x at (~dx)−8 = −dx−9, not −dx−8.
- **Meta id `$9A`** points to `$0000`, so drawing it reads a "record" from zero page. It's the only such id. The port reproduces this, and the fuzzer avoids it because random zero-page bytes then send the read anywhere.
- **Byte-level quirks:**
  - A sprite skipped for wrapping off the screen edge still leaves its x byte in OAM.
  - A sinking object stops at its "lower part" sprite after writing only y and attr.
  - When OAM fills up, every later object is skipped.
  - The burst ring uses the timer value after it is decremented, and writes x before it checks y.
  - The orbit tile index is not clamped.
  - On a player overlay, the hit flash only recolours the main sprite.
