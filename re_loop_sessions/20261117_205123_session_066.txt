The top task is done: the "unread" name-entry character grid in bank 18 is live data, and I found what reads it. All of this comes from reading the disassembly; I didn't check it in the emulator.

**Why no reader was found before:** the session-21 range `18:9F05-9FC1` started 61 bytes too late. The data really starts at `18:9EC2`. It is two tables, each 4 rows × 32 columns. The name-entry code reads them directly with `LDA $9EC2,Y` (5 places in `19:A5A9…A62E`) and `LDA $9F42,Y` (`19:A634`).

- **`NameCellGrid` `18:9EC2-9F41`:** what each cell does.
  - `$FF` = the cursor can't stop there; it keeps moving in the pressed direction and wraps around the edges.
  - `$20` = an ordinary letter.
  - `$F2`/`$F1` = the left/right arrows; `$F0` = END.
- **`NameGlyphGrid` `18:9F42-9FC1`:** the letter tiles: `A-Z`, `a-z`, `0-9` and punctuation, plus a space.
- **Cell lookup:** cell = (`$8B`−`$10`)·16 + `$8A`. So the 4 cursor rows (`$8B` = `$10/$12/$14/$16`) each map to one 32-column row of the tables.
- **Each name letter is saved as two bytes:** a glyph in `player_name` (`$6418+X`) and a top byte in `$6410+X`, which is always `$20` (blank). That answers part of the save-leftovers question about `$6410`; I added a note to that task.
- **Unused alternate letters:** if `$05` is non-zero, the glyph gets +`$32` (except `$10`/`$0C`). `$05` is 0 on the title, so this alternate character set never appears.
- **Overlap with the screen layout:** the 26×10 rectangle drawn on screen (`NameEntryRect`, `18:9DD4`, drawn by `19:A10E`) shares its last 26 bytes with the start of `NameCellGrid`. That's harmless only if those tiles show as blank, which I haven't checked.
