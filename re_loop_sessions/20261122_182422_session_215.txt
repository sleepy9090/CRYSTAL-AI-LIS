**How it works** (new `web/src/game/lagmodel.js`)
- `Machine` counts RAM reads, writes and ROM reads per stage of each main-loop pass. A pass lags when its estimated cycles, plus the interrupts it runs into, go past the next NMI.
- The start line of each pass comes from the length of the previous NMI.
- Sounds queued late in a long pass now start one frame later, as in tools.emu. This fixed the false lag at `$59` f2864 and the sound swap s214 found at `$81` f2596/f2597.
