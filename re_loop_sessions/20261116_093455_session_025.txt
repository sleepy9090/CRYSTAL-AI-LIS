Each sheet uses that area's real sprite graphics banks and palettes. The sheets for areas `$02` (villagers), `$03` and `$11` look clean.
- **`gfx/sprites/index.txt`**: one line per area listing its graphics banks, palettes and sprites.
- **`gfx/sprites.json`**: all 256 sprite records with frames decoded and mirrored versions already flipped, plus each area's graphics banks, palettes and placed objects. It also spells out the drawing rules, for the web port.

**Findings (written to REVERSE.md):**
- **The other two sprite palettes:** palette 0 (player) is normally id 0, switching to `$4D` during one hit-flash mode. Palette 1 (weapon) follows the equipped sword level, clamped to 1–5. The same value picks the sword's graphics bank, so the weapon's tiles and colours change together.
- **Tile offsets pick the graphics bank:** some objects add `$40` (or `$C0`) to every tile number. The bank is chosen from the tile number after that addition, so an offset moves a sprite into a different graphics bank.
- **The sheets show starting frames only:** almost every enemy's AI rewrites its sprite id for facing and poses after it spawns, so the full pose sets belong to the existing "gameplay 3/3" task.
- **Invisible objects:** 229 of the 711 placed objects use an empty sprite. These are triggers and controllers that draw nothing until their AI gives them a sprite. 77 distinct sprites are visible at spawn.
- **Session-8 guess about `$FF` banks:** no object's starting frames read from an area's graphics register set to `$FF`. That supports the guess that `$FF` marks an unused bank, but it hasn't been checked for poses set later by the AI.
- **Animation speed is per enemy type:** there is no global animation timer. Each AI handler steps its own frame counter (about 189 sites), and some step it 2–3 times per frame, so those animate 2–3× faster. The per-type rates are left to "gameplay 3/3".
