I finished session 7's task: decoding the area table plus `LoadAreaChrRecord`. It's marked done in REVERSE.md.

**What the table is:** There's only one table. It sits at `12:9201` (banks 12/13), holds 252 entries, and is looked up by the current area id `$6C`. The `$9301` read is just the upper half of the same table. Besides setting the sprite CHR, each area record is also that area's list of objects to spawn:
- **Record layout:** a `00` byte, then `$07E6`, `$07E7`, R4 and R5, then one 4-byte entry per object slot starting at slot `$0D`, ending with `FF`. An entry starting with `FE`, or with bit 7 set in its second byte, skips that slot.
- **Position:** Y = b0·16+12 and X = (b1&$7F)·16+8, with an extra +8 when b2 bit 6 is set.
- **Spawn type:** b2 bits 0-2 pick one of 5 spawn handlers at `31:E218`, and b3 is a parameter. One handler places collectible items. It checks a bit in WRAM `$6480` and, if the bit is set, spawns object `$4E` instead (probably the "already collected" version).

**New tool:** `tools/area_dump.py list|chr|spawns [areas]` decodes all of this, and I ran it. The `chr` mode groups areas by their R4/R5 pair. There are over 100 distinct pairs; the most common are `4A/4A` (28 areas) and `67/66` (12 areas).

**Check against the sprites:** I rendered the metasprites with `meta_dump.py --chr 40,42,67,66`.
