**Driver behaviour found (in REVERSE.md, "Tick timing + flow exact")**
- **Timing:** each channel counts down its note length first and only reads new commands when the count hits 0. Channels start with length 1. Sound effects wait a frame if the music read 20 or more commands that frame.
- **Loops and calls:** a subroutine call shares its slot with the second loop counter, so a call inside that loop overwrites the loop's state.
- **Quirks the port must copy:**
  - The octave command reads its value from inside the code: octave 0 gives octave 7, and values 9 and up give junk bytes.
  - A vibrato "wait" command (values 9 and up) leaves a bad vibrato depth behind.
  - The fade timer counts down once per channel, not once per frame, so fades run 4–6 times faster than the timer value suggests. Fading cuts the triangle channel at once.
- **Volume:** the output volume table works out to `max(env + base − 15, 1)` when both values are above 0, otherwise 0.
- **Drums:** a drum command picks the drum, and every later noise note on that channel replays it. All drums are one 993-byte sample at `31:FA00–FDE0`, played at different speeds. Its end at `$FDE0` explains why the leftover junk data in that bank starts at `31:FDE0`.
