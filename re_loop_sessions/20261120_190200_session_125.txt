I fixed the one-frame-early pause window in area `$5F` (f2692 in `pause5f.json`), the last open item of the SELECT-menu leftovers task, so that task is now marked done. All 8 web checks pass. Nothing is committed.

**Cause:** the PPU frame timing in the port, not the ported game code.
- While building the window, `PauseScreen` switches the nametable shadow to nametable 2 (`15:BCEC`). The next `PpuQueueBlock` writes PPUCTRL from that shadow (`30:C4BE`), thousands of cycles after the NMI.
- On real hardware that write comes too late to move the next frame vertically, because the vertical scroll bits are copied at the pre-render line, about 20 lines after the NMI.
- The port copied all of the scroll register after the main code had run, so f2692 showed nametable 2 still drawn with the game's tile graphics. The emulator only switches to the window one frame later, together with the window's tile graphics.
- I only saw this in area `$5F`. The area-1 pause run from session 94 has no such frame; I didn't check why.

**Fix:**
- `web/src/nes/ppu.js`: new `latchVert()`. `renderFrame` now takes the vertical scroll bits from the value saved after the last NMI and the horizontal bits from the current register.
- `web/src/game/machine.js`: `runFrame` saves that value after the NMI, and `loadState` saves it too.
