**Correction to an earlier session:** `24:$8000` is not a table of pointers to sound data, as session 6 recorded. It is the jump table for the sound stream's commands. Each stream byte's high nibble picks one of 16 handlers, through `24:8347` (now labelled `SndReadOp`).

**What's decoded:**
- **Music:** the header table is at `24:8C0C` and covers ids `$00-$1F`; ids `$02`, `$05` and `$10` are empty. Each header is one byte the code never reads, then pointers to 4 channel streams (two square, triangle, noise). Id `$00` is a silence track.
- **Sound effects:** the header table is at the very start of bank 12, which the driver maps in at `$A000`. It covers ids `$20-$77`. Each header is a priority byte (lower wins) followed by two stream pointers, one played on the second square channel and one on noise. While an effect plays, the matching music channels are muted but keep running.
- **Commands:** I worked out all 16: note, octave, rest, note length (32-entry table of frame counts), legato, volume, duty, jump/loops, sweep, detuned note (on the noise channel this triggers a sample drum), envelope, vibrato, and end. "End" sets the next music id, which is how tracks loop or chain.
- **Notes:** the low nibble of a note byte is the note's hex letter: C, D, E, F, A, B are literal, `0`=G, `1`=C♯, `2`=D♯, `4`=F♯, `5`=G♯, `6`=A♯. I checked this against the period table (C = `$6AC` ≈ 65.4 Hz, which is C2).
- **Ids the game uses**, from the 67 places that load a fixed id before calling `PlaySound`:
  - Music: `$00`, `$0C` and `$12` (8 sites), plus `$80` and `$93`, which force-restart `$00` (stop) and `$13`.
  - About 40 distinct sound-effect ids; `$29` is the most common.
  - One call site (`26:92D6`) asks for `$44`, which is an empty slot, so it plays nothing.
  - The other ~18 callers load the id from RAM or a table, and I didn't list those.
