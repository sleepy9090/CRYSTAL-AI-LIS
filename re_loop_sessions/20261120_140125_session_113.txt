**ROM behaviour the fuzz turned up**
- **Stone-shot bug in the game itself:** when an enemy's stone shot actually stones the player, a palette rebuild leaves the Y register at 4. The shared "remove the shot" code then clears slot 4 (a player-shot slot) instead, so the stone shot stays alive. The port copies this exactly.
- When the screen is off, the HUD redraw routine leaves Y as the queue flush set it (e.g. `$80`) rather than 2×6. This changes one byte, the saved sound Y at `$010F`. To match it, `ppuQueueFlush`, `queueFlushNow`, `hudQueue` and `hudRedraw` now return their exit Y. Nothing else used their return values.
