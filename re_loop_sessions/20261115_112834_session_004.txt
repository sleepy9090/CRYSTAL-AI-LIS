**What I found:**
- **Duty command (`9x`, `24:854D`):**
  - On the triangle channel, x becomes the high nibble of the `$4008` shadow register.
  - On the square and noise channels, bit 0 of x turns on constant volume and bits 1–2 set the duty; the length-halt bit is always set. When bit 0 is 0, the channel's software envelope is switched off.
- **Vibrato (`24:86AA`):** the full per-frame algorithm is now in REVERSE.md, including both lookup tables (`24:8714` and `24:8724`, one row of pitch offsets per octave). A few behaviours a web port needs to copy exactly:
  - Only the low byte of the period is changed, and only when the high byte would stay the same.
  - The base pitch is never changed, so the wobble doesn't drift.
  - An odd depth runs at half speed.
  - When an envelope is active, vibrato waits until the envelope reaches its last step.
- **Bug in the original game:** the vibrato table lookup is off by one entry. With depth 0 or 1 in octave 0, the offsets cycle 0, −4, 0, +8 instead of evening out. At octave 7 with depth 6 or 7, it reads 2 bytes past the table end and gets +256. The port should reproduce this.
- **Empty sound-effect slots:** I checked all 88 entries. The new empty ones are `$59 $70 $71 $73 $77`, making 14 in total.
- **Music tracks, named by what calls them:**
  - **`$13` is a short jingle (about 2.5 s) that interrupts the current music.** The caller first marks the current track to be restarted, so the previous music resumes when the jingle ends. It plays instead of sound effect `$29` or `$3F` in two special cases, so it's likely an item or achievement fanfare.
  - **`$12` is a full looping track** started by 8 handlers in the entity-logic bank (bank 15), only when `$07D5` is non-zero. It's likely boss or encounter music.
  - **`$0C`** has a single caller, an event handler at `15:B310`; what it's for is still unknown.
- I added labels for `SndVibratoTick`, `SndVibStepTable` and `SndVibOffsetTable`, and rewrote the `SndOpDuty` label.
