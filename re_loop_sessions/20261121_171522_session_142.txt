I finished sub_state 13 `PauseWait` (`15:BDDB`), the next item in the remaining-substates task. It turned out to need no new game logic. The loop was already ported inside `pauseScreen` back in s94, so I only had to wire up the dispatch-table entry.

**What I found:** entry 13 can never be reached in the ROM.
- **Nothing sets it:** none of the 70 places that write `sub_state` (`$41`) stores 12 or 13. 69 write fixed values, and the one variable write (`AiSetSubstate` `27:A5C5`) only gives `$20-$23`.
- **It is only ever 13 inside the pause loop:** `PauseScreen` increments it to 13, and its wait loop never returns to the dispatcher.
- **Reaching it would crash:** the routine's final `PLA` would pop the main loop's return address (`$C918`, pushed at `30:C916`). `irq_mode` would get `$18`, and the `RTS` at the end of `ReadPads` would jump into garbage.

**Port changes:**
- In `web/src/game/states/pause.js`, the wait loop is split out as `pauseWait`, and `pauseScreen` falls into it as the ROM does.
