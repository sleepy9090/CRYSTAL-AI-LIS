I built the two search tools from the top Next Tasks item, `tools/search_bytes.py` and `tools/xref.py`, and tested them against addresses we already know. That task is marked done.

- **`search_bytes.py`** searches PRG (or CHR with `--chr`) for a hex pattern, where `??` matches any byte. It reports hits as `BB:AAAA` plus the file offset, and can show surrounding bytes (`--context`), disassemble each hit (`--disasm`) or limit to one bank (`--bank`).
- **`xref.py`** finds every instruction that references an address, including zero-page addresses and branches within the same bank. It drops matches that look like data rather than real instructions (`--loose` shows them anyway). It can also find raw 16-bit pointers (`--data`) and an address loaded as separate low/high byte values (`--imm`).
- **Shared helpers** added to `nesrom.py`: `bank_window`, `bank_cpu_addr` and `parse_bank_addr`.

**Test results:**
- `xref.py C40E` found 48 calls to `SwitchBank16`, all in the fixed banks 30 and 31. The swappable banks never call it themselves, so bank switching is always driven from fixed code.
- `xref.py 40 --bank 30` found the 3 places that read or write the main state variable `$40`: `C904`, `C977` and `C9F5`.
- `--data` found a real pointer at `31:F422` (`.dw $F421`). Reset reads it to set the initial IRQ vector at `$0054`. I added it to `labels.csv` as `IrqDefaultPtr`.
- `--imm` found nothing for `F421`. That's correct: Reset loads the vector from that pointer word, not as two immediate values.
- The pattern `A9 ?? 20 0E C4` finds the `LDA #n / JSR C40E` call sites, which the next task (mapping which 16KB bank holds which subsystem) needs.
