I finished this session's task. Bank 24/25 is the sound driver. Bank 28 `$800E` is not sound code; it draws game objects as sprites.

**How I confirmed it:** I searched every swappable bank for direct writes to the sound hardware registers. All 19 hits are in bank 24 and bank 28 has none.

**How sound works, from the game's side down:**
- **`30:C125` PlaySound** is the call the game uses to start a sound, from 85 places in the code. A = sound ID. IDs below `$20` are music and are skipped if that track is already playing. IDs `$20` and up are sound effects. Each request goes into a 6-slot queue at `$0103-$0108` (count in `$0100`, a lock byte in `$0101`).
- **`31:F7FE` SoundUpdate** runs every frame from the vblank interrupt and from some of the scanline interrupt handlers. It maps banks 24/25 in, takes at most one ID from the queue per frame, runs the per-frame player, then puts the previous banks back.
- **Inside bank 24:**
  - `$8020` silences everything and is called once at reset.
  - `$8048` handles one command: none, pause toggle, start music or start a sound effect.
  - `$8094` starts a sound effect. It maps bank 12 in, so the sound-effect pointer table effectively starts at `12:$A000`. The first byte of each effect is a priority, so a lower-priority effect can't cut off one that's playing.
  - `$80E4` starts music on 4 channels.
  - `$8186` is the per-frame player.
- **`24:$8000-$801F`** is a table of 16 pointers to sound data. That's why the bank's code starts at `$8020`.

**Bank 28 `$800E`:** it loops over game objects, subtracts the scroll position from each object's position, and builds sprite data. Each call it decrements `$07FF` and uses it to pick a different starting object, so sprites flicker in rotation when too many share a line.
