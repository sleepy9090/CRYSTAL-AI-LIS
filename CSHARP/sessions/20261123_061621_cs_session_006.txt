**What's in it** (one file per web module, with `// js:` tags):
- **`Program.cs`** (main.js):
  - The window scales by whole numbers, stays centred and can be resized.
  - The game runs at a fixed 60.0988 Hz and never runs more than 250 ms of frames to catch up.
  - P pauses, M mutes, and minimising the window pauses too.
  - The pause/mute message shows in the window title.
- **`Input.cs`** (input.js): the same key layout as the web page (arrows/WASD, X/K = A, Z/J = B, Enter = Start, Right Shift/Tab = Select), plus a game controller (buttons, d-pad and left stick). Controllers can be plugged in while it runs, and keys are released when the window loses focus.
- **`Audio.cs`** (audio.js): APU sound through SDL's audio queue, with the web port's buffer size, start-up delay and volume. One addition the web port doesn't have: if more than 0.25 s of sound is waiting to play, it drops the newest batch so the delay doesn't keep growing.
- **`Save.cs`** (save.js): the battery save is kept as the raw 8 KB in `CSHARP/re-c.sav`. It's saved every ~5 s when it changed and again on exit. The write goes to a temporary file first, so a crash can't leave half a save.
- **`Sdl.cs`**: hand-written bindings to `libSDL2-2.0.so.0`, no NuGet packages.

**Things I added that the web port doesn't have:**
- Options `--scale`, `--save`, `--load-state`, `--mute`, `--no-audio`, `--frames N`, `--turbo` (runs as fast as possible) and `--dump-screen`.
- Esc quits.
- Starting from `--load-state` writes no save unless you also give `--save`, so a test state can't overwrite your real save file.
